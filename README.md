# 鲲鉴智策 · 可解释时序预测与决策平台

> 面向水产供应链中小企业的可解释时序预测与经营决策平台
> 纯前端 · 离线可用 —— 打开网页即可完成「训练 → 回测 → 归因 → 决策」

> **评审体验账号**：账号 `admin` · 口令 `admin123`（登录页口令框右侧「一键填入」按钮可自动填好）
> 系统已内置约 120 天、1488 条演示送货数据，登录后即可体验全部模块，无需注册、无需导入数据。

## 一、项目简介

水产批发这类行业的数据有个共同特点：**样本少（200~1200 条）、没有专职数据分析人员、也负担不起云端的 AI 服务**。市面上的预测工具要么要求上传数据到云端，要么配置复杂到小企业用不起来。

鲲鉴智策把七个时序预测模型（其中三个是我们自己设计的结构）和一套时间切片归因方法全部用原生 JavaScript 重写，跑在浏览器里：**不联网、不上传数据、不依赖任何深度学习框架**。店员在手机上打开网页，导入自己的送货单 Excel，点一次「开始预测」，大约 99 秒后就能拿到未来 7 天的销量预测、每个预测值的归因解释，以及一份可以直接打印的经营决策报告。

系统同时包含送货明细、智能对账、客户管理、数据治理四个业务模块，形成「录单 → 对账 → 预测 → 决策」的完整闭环，而不是一个孤立的算法演示。

有对话式数据分析助手**「秦思智能体」**：登录后右下角随时唤起，用一句大白话完成数据查询、分析与可视化——「东星斑 9 月卖了多少」「本月比上月怎么样」「画最近 30 天趋势图」，回答自带数字结论、内嵌图表和一键跳转，让不会用筛选器和报表的人也能把数据用起来。

### 4.3 模型与算法

七个模型全部以原生 JS 实现，包含前向传播、反向传播与 Adam 优化器，没有使用 TensorFlow.js 等运行时：

| 模型 | 类型 | 核心思路 |
|---|---|---|
| PatchTST | Patch 注意力 | 序列切 patch 作为 token，正弦位置编码 + 编码器 |
| PhaseFormer | 谱域注意力（自研） | rFFT 取 6 个频带的幅值/相位作 token，单头自注意力 |
| MixLinear | 混合线性专家（自研） | 三个视图的岭回归专家 + 7 维特征门控加权 |
| FreqLite | 频域滤波残差栈（自研） | 可学习复数增益滤波 + 残差 MLP，三子网集成 |
| Transformer | 自注意力 | 逐点 token + 均值池化 + 线性输出头 |
| LSTM 集成 | 循环网络 | 单层 LSTM + BPTT，三个子网取平均 |
| 轻量 TCN | 膨胀因果卷积 | 3 层膨胀卷积 + 残差连接，直接输出多步 |

**实测结果**（演示数据集，24 个留出日）：

| 排名 | 模型 | MAE | RMSE | WAPE(%) | DM p |
|---|---|---|---|---|---|
| 1 | PatchTST | 1904.1 | 2459.7 | **8.50** | — |
| 2 | MixLinear | 1991.8 | 2680.2 | 8.89 | 0.767 |
| 3 | 轻量 TCN | 2084.3 | 3011.1 | 9.30 | 0.341 |
| 4 | FreqLite | 2231.6 | 3274.1 | 9.96 | 0.390 |
| 5 | Transformer | 2349.7 | 2713.5 | 10.48 | 0.102 |
| 6 | LSTM 集成 | 2381.9 | 2721.7 | 10.63 | 0.221 |
| 7 | PhaseFormer | 3208.5 | 3949.4 | 14.32 | 0.005 |

DM p 为相对推荐模型的 Diebold–Mariano 检验 p 值。前四名的差异在 5% 水平上并不显著，系统如实呈现这一结论，没有夸大模型之间的差距。

### 4.5 AI 能力设计（与评分项对照）

系统采用**双引擎**：本地规则引擎负责 13 类高频确定性问题（零延迟、可离线）；大模型 Agent 负责开放性问题。**未配置密钥时自动降级为本地引擎，系统照常可用**，这是"AI 安全可控"的一部分，而不是功能缺失。

| 评分项 | 落地实现 | 代码位置 | 演示方式 |
|---|---|---|---|
| **大模型集成质量** | OpenAI 兼容统一客户端：对话 / 视觉 / 语音转写三条通道；超时（45s）+ 失败重试 + 错误分类（401/429/5xx/超时）；用量统计；结构化 JSON 容错解析；系统提示词内置职责边界、引用纪律、字数上限 | `js/ai/llm.js`、`js/ai/agent.js`（ROLE） | 点 ⚙ 填地址与密钥 → 「测试连接」→ 提问开放问题 |

5. 如需导入自己的数据：「数据服务中心 → 导入 Excel 送货明细」，可先下载模板。

| `LLM_VISION_MODEL` | 视觉模型（图片识别） | 留空沿用对话模型，需该模型支持图像输入 |

配置链路：`.env`（不入库）→ `node scripts/build-env.mjs` → `js/env.js`（空值模板入库）→ 页面读取 `window.KJ_ENV`。

```bash
copy .env.example .env            # 1. 复制模板（macOS/Linux 用 cp）
# 2. 编辑 .env，填入实际值；.env 已在 .gitignore 中排除
node scripts/build-env.mjs        # 3. 生成 js/env.js
node scripts/build-env.mjs --empty  # 4. 提交公开仓库前还原为空值模板
```

- 也可不建 `.env`，改为在 GitHub Actions / 部署平台的**环境变量面板**配置同名变量，构建期执行同一脚本（脚本优先读取进程环境变量，白名单之外的变量一律忽略）；
- 仓库内只保留 `.env.example` 模板与空值 `js/env.js`，**任何真实密钥都不得提交**；脚本输出只打印掩码，避免真实值进入 CI 日志；
- 未注入配置时业务代码回落到本地调试兜底值（`admin` / `admin123`），保证"下载即用、双击可跑"。

## 六、常见问题

**Q：预测要等 99 秒，是不是卡住了？**
A：训练在主线程分片执行，每片之间会让出一次事件循环，进度条会实时走。低端手机上可能延长到 2 分钟左右，属正常现象。

**Q：为什么预测结果和别人的不一样？**
A：所有模型使用固定随机种子，同一份数据、同一参数下结果完全可复现。若数据被修改过（增删送货记录），结果自然不同。

**Q：可以换成自己的数据吗？**
A：可以。在「数据服务中心」下载导入模板，按列填写后导入；字段缺失会在导入时提示。

**Q：数据存在哪里？会上传吗？**
A：全部存在浏览器 localStorage，页面不发起任何网络请求。
